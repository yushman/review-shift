# review-shift

**review-shift ночью ревьюит локальные git-ветки и к утру кладёт на стол отчёт и готовый
к применению git-патч — вместо ревью, которое откладывается до момента после мержа.**

[English version](README.md)

> **Статус: выпущен v0.1.0.** `pipx install review-shift` ставит его из PyPI.

---

## Что он делает

Ночью, без человека рядом, `review-shift`:

1. находит локальные ветки, которые недавно двигались (`refs/heads/`, по committer date);
2. строит дифф каждой ветки против точки ветвления с базовой веткой;
3. маскирует значения секретов до того, как что-либо уйдёт модели;
4. прогоняет read-only код-ревью заданной глубины;
5. пишет markdown-отчёт, `findings.json` и два файла патчей — причём каждый патч перед
   записью на диск проверяется через `git apply --check`.

Утром вы читаете один файл и применяете один патч. `review-shift` ничего не применяет сам,
не коммитит, не пушит и не трогает рабочее дерево.

## Требования

- macOS для запуска по расписанию (`launchd`), машина на питании от сети и не спит — см.
  «Ограничения». Сам CLI работает на Linux и macOS, x86 и ARM.
- CLI [Claude Code](https://claude.com/claude-code) **версии 2.1.0 или новее**, уже
  залогиненный.
- Python 3.11+.

## Основной сценарий

```bash
# подготовить репозиторий: создаётся .review-shift/config.yml,
# артефакты прогонов исключаются из git
cd ~/proj/myrepo && review-shift init

# проверить окружение, прежде чем доверять ему ночь
review-shift doctor

# поставить ночной прогон (генерируется launchd-джоба, регистрируется пробуждение)
review-shift init launchd
```

Утром:

```bash
$EDITOR .review-shift/runs/latest/report.md
```

## Демо

```bash
asciinema play demo/review-shift.cast
```

Находки в записи — сценарий ради быстрого, бесплатного и воспроизводимого прогона: `init` и
артефакты патча/отчёта в записи настоящие, произведены тем же кодом (`patch.resolve` /
`patch.generate_and_verify` / `report.render`), что и реальный ночной прогон — запись
пропускает живой вызов модели, который делает `review-shift run`, а `doctor` в записи не
запускается вовсе, потому что его проверка авторизации — тоже живой вызов.

## In-session ревью (`/review-shift`)

`review-shift` также работает изнутри сессии Claude Code как скилл, который вызывает тот же
CLI (ADR-006) — те же промпты, тот же лок, тот же отчёт. Ограничение — одна ветка и
`depth <= medium`. Два способа получить его, не взаимоисключающие:

```bash
# без зависимости от маркетплейса, точная команда `/review-shift`, без авто-обновления
review-shift init skill
```

```
# внутри сессии Claude Code: self-hosted маркетплейс, авто-обновление, namespaced-команда
/plugin marketplace add https://github.com/yushman/review-shift
/plugin install review-shift@review-shift
# вызывается как /review-shift:review-shift (Claude Code всегда добавляет плагину префикс)
```

`init skill` пишет `.claude/skills/review-shift/SKILL.md` в текущем репозитории; перезапустите
её после обновления `review-shift`, чтобы подхватить изменившийся скилл. Оба канала можно
поставить одновременно — Claude Code держит рядом и исходный `/skill-name`, и копию плагина.

## Как применить патч

Осознанно вручную и осознанно в три шага. Патч привязан к вершине ветки на момент прогона.

```bash
# 1. sha, против которого собран патч, — в заголовке патча и в run.json
git -C . rev-parse feature/payments-v2

# 2. проверить применимость
git switch feature/payments-v2
git apply --check .review-shift/runs/latest/patches/auto_fixed.patch

# 3. применить
git apply .review-shift/runs/latest/patches/auto_fixed.patch
```

Если ветка ушла вперёд от этого sha, CLI печатает объяснение вместо рецепта, а не делает
вид, что патч всё ещё применим.

## Что появляется на диске

```
.review-shift/
├── config.yml                  # предназначен для коммита
└── runs/
    ├── 2026-08-22T03-30-00Z-feature-payments-v2/
    │   ├── report.md           # то, что читаете утром
    │   ├── findings.json
    │   ├── run.json            # ветка, sha, глубина, стоимость, тайминги, счётчики
    │   ├── events.jsonl
    │   └── patches/
    │       ├── auto_fixed.patch  # severity >= patch.auto_fix_min_severity, по умолчанию high
    │       └── all.patch
    ├── index.json
    └── latest -> …
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Прогон завершён, critical нет |
| 1 | Прогон завершён, есть critical findings — сигнал, а не ошибка |
| 2 | Внутренняя ошибка (конфиг, git, невалидный вывод модели, hard-timeout) |
| 3 | Другой прогон уже идёт |
| 4 | Ошибка аутентификации или исчерпана квота |

Шаблоны планировщиков передают `--exit-zero-on-findings`, чтобы ночь, в которую честно
нашлись проблемы, не выглядела как упавшая задача.

## Ограничения — прочитайте

- **Закрытый ноутбук на батарее не проснётся.** `launchd` не будит машину; прогон уедет на
  момент следующего пробуждения, то есть слишком поздно, чтобы быть полезным. Инструмент
  регистрирует пробуждение через `pmset` и оборачивает прогон в `caffeinate`, но ни то, ни
  другое не спасёт машину с закрытой крышкой на батарее.
- **Ваш код уходит провайдеру модели.** Проверьте политику работодателя и условия вашего
  плана, прежде чем направлять это на рабочий код.
- **Маскирование секретов снижает риск, но не гарантирует ничего.** Regex-эвристики
  промахиваются на кастомных форматах токенов, а у агента есть собственный доступ к
  файловой системе. Не для кода под регуляторными ограничениями.
- **Цифр о качестве пока нет.** Recall и precision заявляются только после появления
  бенчмарк-стенда (v0.2). Что меряет v0.1 — применимость патчей.
- **Артефакты прогонов содержат фрагменты кода** и лежат в рабочем дереве.
- **Скоуп v0.1:** глубины `low` и `medium`, только локальные ветки, один репозиторий на
  прогон. Диффы больше ~2 000 изменённых строк пропускаются с явной причиной, а не режутся
  молча. `high`, chunking, retention и инкрементальное ревью — v0.2; remote-ветки и работа
  по PR — v0.3.
